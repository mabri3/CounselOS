# Issue Map

1. **Decision taxonomy.** Identify which outcomes are adverse action and which timing and content rules apply to each business-credit segment.
2. **Specific reasons.** Test whether generated reasons accurately describe the principal factors actually used for the individual decision.
3. **Reason-code translation.** Prevent broad labels from hiding specific model logic, and prevent a feature-importance tool from producing a reason the model did not use as a principal factor.
4. **Fair-lending risk.** Review comparative outcomes, model inputs, proxy risk, interaction effects, overrides, and less-discriminatory alternatives.
5. **Device-data purpose.** Decide whether underwriting is compatible with the notice, consent, contract, and user expectation attached to security data.
6. **Manual review.** Define when low-quality data, unusual feature combinations, or reason-code mismatch requires human review.
7. **Change control.** Set approval, monitoring, drift, complaint, and rollback requirements with the bank partner.
8. **Recordkeeping.** Preserve the model version, input snapshot, outcome, reasons sent, and any override for each decision.
