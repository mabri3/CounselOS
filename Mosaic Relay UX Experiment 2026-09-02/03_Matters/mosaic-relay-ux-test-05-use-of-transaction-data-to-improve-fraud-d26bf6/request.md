# Original Request

Mosaic Relay wants to use transaction metadata from multiple merchants to train a fraud-detection model. The data would include device signals, payment method details, transaction amounts, merchant category, location at a broad regional level, dispute outcomes, and account events. The proposed operation would remove direct identifiers, combine data across customers, and retain the training set for seven years. The actors are Mosaic Relay, merchants, payers, recipients, fraud vendors, cloud providers, and model-governance staff. Model training would occur monthly, with model outputs used in real-time authorization and payout decisions.

Known facts are that the data is collected while providing payment and fraud services, and Mosaic Relay would not sell the data. The company believes aggregation and pseudonymization reduce privacy risk. Missing facts include the exact identifiers retained, whether device data is treated as personal information in each location, contractual limits imposed by merchants, consumer notices and opt-out rights, cross-border transfers, automated-decision disclosures, and deletion procedures. Legal advice is requested on lawful purposes, controller and processor roles, contract language, notice requirements, retention, de-identification standards, and whether the model’s decisions require human review or additional consumer rights.
