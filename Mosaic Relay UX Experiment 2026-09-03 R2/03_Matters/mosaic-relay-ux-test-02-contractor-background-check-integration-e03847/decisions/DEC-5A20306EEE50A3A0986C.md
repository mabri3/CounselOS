# Mosaic Relay UX Test — 02 — Contractor Background-Check Integration

## Chosen path

Defer screening-linked payout gating until the seven launch conditions are verified; if timing requires, permit only non-gating informational screening.

## Rationale

High-risk regulatory analysis. Unknown report/CRA status, launch states, final decision-maker, and adverse-action ownership make an unconditional launch unsafe. The platform must own decisions and notices; Mosaic Relay should receive only minimal status metadata and must not auto-deny.

## Recommendation disposition

Followed

## Conditions

- Platform is sole decision-maker; no automatic denial; human review and kill switch
- Vendor CRA status, report catalog, data sources, match logic, and arrests/convictions confirmed
- Launch states fixed with state-by-state fair-chance and adverse-action matrix
- FCRA consent, authorization, pre-adverse and final notices implemented
- Dispute/reinvestigation path, pause, SLAs, and escalation tested
- Status-code-only data flow, least privilege, logging, retention/deletion, and security verified
- Customer/vendor agreements allocate FCRA, privacy, security, audit, indemnity, insurance, and regulatory duties

## Not decided

- Final decision-maker and adverse-action owner not yet confirmed
- Exact reports, data sources, vendor API schema, and state coverage not provided
- Whether reports are consumer reports and vendor is a CRA not verified
- Whether any payout hold is adverse action and whether contractors are treated as employees in any state not verified
